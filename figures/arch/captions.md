# Architecture Diagrams — Captions, Purposes, and Placement

All figures are schematics (no fabricated data plots; reported simulation values quoted only where the papers print them). Rendered at 200 dpi, shared visual language: warm-gray ground, muted blue/sage/terracotta/gold accents, sans-serif labels, rounded component shapes, labeled arrows. Symbol registry: master law S(t+1) = S(t) + λ⁺max(ε,0)r + λ⁻min(ε,0)r − δ_S(S−S_base); ε = V−E; ε̃ = (V−E)/s_d; ι(T) = tanh(w·T̃); ψ (observation-salience dissipation); ℓ (observation leakage); R (Kuramoto order parameter); D/O/C/A/S = the five channels (Expectation/Validation/Recognition/Activation/Stabilization) — never "five-stage sequence"; ζ (densification; κ retired) does not appear in these schematics.

## TFP (protocol paper — strictly mathematical, vendor-agnostic, open-source)

### 1. `tfp_protocol_stack.png`
**Caption.** The Fresh Protocol as a five-layer stack of mathematical objects. L1 measurement/evidence: typed validation events (E, V, timestamp, attestations) and the provider-signature attestation relation (presence + authenticity). L2 identity & data: W3C DIDs, selective-disclosure credentials (SD-JWT, RFC 9901 — predicates, not records), database-per-tenant ownership locality. L3 validation/compute: the estimator interface, the master law (TFP preset λ⁻ > λ⁺), ε̃ normalization, the ι(T) trust index and the bounded exponential-tilt EU(a|T). L4 commitment/settlement & audit: hash-chained state-transition anchors, Merkle-batch rollups, light-client verification, per-event micropayment settlement. L5 consumption: applications via an application-supplied loading matrix; no domain logic in the protocol. The core flow AUTH → DID → DB → HASH (left rail) and the cross-cutting/population-level objects ψ (observation salience), R (phase coherence), and the attestation boundary (right rail) are drawn outside the layers because no single layer owns them.
**Purpose.** Locate every theoretical claim of the paper on one layer map, so each later section's claim can be pointed at a layer and an interface.
**Target.** TFP paper — §3 Architecture (Figure 1, "TFP reference architecture").

### 2. `tfp_ev_dataflow.png`
**Caption.** The expectation–validation loop. A recorded expectation E_t and a provider-attested outcome V_t form the normalized mismatch ε̃_t = (V_t−E_t)/s_d, which drives the master-law update S_{t+1} = S_t + λ⁺max(ε,0)r + λ⁻min(ε,0)r − δ_S(S_t−S_base) with the TFP preset λ⁻ > λ⁺ (break/build asymmetry), r ≡ 1, δ_S ≥ 0. The state projects through ι(T) = tanh(w·T̃) into trust-weighted expected utility (exponential tilt P̃ ∝ P·exp(γ·ι(T)·û(o))), which selects the next interaction and thereby the next expectation — the feedback path. Every state transition is hashed to the audit anchor. The observation term (dε = −(μ+ψ(m))ε dt + σ dW) is annotated as the regime the loop runs under; the E-side is marked un-attested (§3.8 scope limit).
**Purpose.** Show the mathematical heart of the protocol — one signed mismatch per event driving one state update, with the loop closed through ι(T) — and where the audit and observation terms attach.
**Target.** TFP paper — §2 (design principles) / §3.3 (validation/compute layer); candidate Figure for §3.0–3.3.

### 3. `tfp_leakage_model.png`
**Caption.** The observation-leakage model. Top: leakage ℓ ∈ [0,1] degrades the feedback channel two compounding ways — coupling attenuation K_eff = K(1−ℓ) and observation noise θ̂_j = θ_j + η_j, η_j ~ N(0,(πℓ/2)²) — so the adversary's view decorrelates from the true state as ℓ rises (at ℓ = 0.9, σ_η ≈ 1.41 rad). Middle: what each stored artifact reveals — a provider-signed event reveals that event's existence and authenticity only; a hash anchor reveals that a transition occurred, never content; an opt-in aggregate-liability predicate reveals one predicate bit (minimal-disclosure path) — versus the custodial path, where one compromise of the full-record vault exposes 100% of records (Equifax 2017 anchor; per-tenant conditional exposure 0.2% at N = 500, Sim P2). Bottom: the leakage budget — the protocol's four responses minimize salience m (hence ψ) and hold ℓ under the coherence fragility threshold ℓ* ∈ [0.02, 0.10] at K = 4.5.
**Purpose.** Bound information leakage per artifact and tie the privacy architecture to the quantified coherence cost of leakage (Sim P1b).
**Target.** TFP paper — §3.6 (Sim P1b) / §4 (observation distortion); supports §3.8–3.9.

### 4. `tfp_attestation_completeness.png`
**Caption.** Provider-attested validation flow and the integrity/completeness distinction. Providers sign good and bad events; events enter the participant's hash-chained, owner-held record, are Merkle-batched, and anchor to the audit chain. An omitted adverse event breaks no hash chain: attestation proves presence and authenticity, never absence (banner). Four mechanisms convert integrity toward completeness — (1) transparency log + verifier refuse-or-flag policy (Certificate Transparency, RFC 6962); (2) non-equivocation via signed state roots and consistency proofs (CONIKS); (3) counterparty co-signing (double-entry bookkeeping; PeerReview); (4) the opt-in aggregate-liability proof restoring cross-provider visibility without a custodian. Scope limit: the expectation (E) side is un-attested.
**Purpose.** Make the integrity-vs-completeness distinction visual and precise, and enumerate exactly which mechanisms the protocol relies on for completeness.
**Target.** TFP paper — §3.8 (completeness vs. integrity).

### 5. `tfp_pas_coherence.png`
**Caption.** Partial attestations compose into coherence. Each provider-signed event fixes one agent-local phase θ_k = 2 arctan(ε̃_k); bilateral validation edges are the Kuramoto coupling K; the order parameter R·e^{iΘ} = (1/N)Σ_k e^{iθ_k} measures population alignment. Schematic phase renderings: isolated agents (K = 0) sit at the 1/√N incoherent floor (R ≈ 0.04); the coupled population (K = 4.5) phase-locks (R = 0.739 ± 0.029, Sim P1 verification re-run). Coherence is a property of the coupling, not of the agents, and is fragile to leakage (K_eff = K(1−ℓ); ℓ* band at the operating point); phases accrue from attested events in wall-clock time (the Sim P8 time floor), so accumulation cannot be compressed.
**Purpose.** Show how collective coherence emerges from local, partial attestations — and that it is the feedback composition, not isolation, that produces it.
**Target.** TFP paper — §3.6 (Sim P1/P1b); complements the R(K,ℓ) surface figure.

## FreshCredit whitepaper (implementation — named production technology, commercial)

### 6. `wp_implementation_stack.png`
**Caption.** The implementation architecture with named production systems. Data ingress (left): Plaid (Link → public_token → access_token; Auth/Transactions/Identity/Balance products; webhooks — user credentials never touch the app) and Apple HealthKit (on-device HKHealthStore only, per-type authorization, no cloud API; physiology sequestered from decisions). User device (center): FreshCredit app holding the edge libSQL database (embedded replica; local µs reads, writes to the remote primary with read-your-writes, async other replicas, AES-256 at rest, user-held keys), the edge estimator computing ΔS = λ(V−E) locally, the Microsoft Authenticator wallet (DIDs, VC keys, selective disclosure), and the Smoldot light client (no trusted RPC). Identity (right-center): Microsoft Entra Verified ID (Request Service API issuance/verification flows, did:web trust anchor, Microsoft Resolver) and Entra Agent ID (blueprint → agent identity → audience-scoped token → MCP/A2A tool calls; sponsor + Conditional Access). Anchor (right): Substrate parachain block path (collator → parablock+PoV → paravalidators → relay chain, GRANDPA finality), Bulletin-chain content-addressed anchoring (Blake2b-256 CID, authorized store, ~2-week renewable retention), NOMT state-store inset. Settlement: x402 (402 challenge → EIP-712/EIP-3009 gasless signature → X-PAYMENT retry → facilitator /verify + /settle → USDC on Base; facilitator non-custodial and swappable).
**Purpose.** Prove the protocol is buildable today from documented, production-grade components, and show exactly where each vendor sits and which arrows carry what.
**Target.** Whitepaper — §3 (architecture); the "protocol unchanged at the core" figure.

### 7. `wp_pipeline_channels.png`
**Caption.** Report → Score → Offer mapped to the five channels. REPORT = D (Expectation): the user-owned record is the market's expectation of the user. SCORE = O (Validation) + C (Recognition): trust-weighted utility over the financial validation stream, registering confirmation or mismatch ε = V−E. OFFER = A (Activation): adaptive matching with adverse-action reason codes from financial features only. S (Stabilization) closes the loop: each completed obligation updates the record by the stability law and becomes the next expectation. The master-law estimator sits in the middle reading exclusively the provider-attested financial stream. Below the literal wall: the physiological stream (HealthKit/wearables) feeds only the user's own-loop (trustor-side) estimator for DOCAS theory validation; the boundary is schema-level, with on-chain weight-checkpoint audit and reason codes that cannot reference physiology — physiology never enters decisions.
**Purpose.** Tie the product narrative to the D/O/C/A/S channel taxonomy and draw the physiology sequestration as a hard, auditable boundary rather than a policy promise.
**Target.** Whitepaper — §3.1 (credit pipeline as externalized DOCAS loop) and §3.2 (dual measurement layers, hard boundary).

### 8. `wp_custodianship_shift.png`
**Caption.** The custodianship paradigm shift. Left: the incumbent centralized star — three nationwide bureaus as a single honeypot; one compromise reaches 100% of records (Equifax 2017: 147.9M records, > $1.4B); identity re-purchased per query ($50–$110+ per pull). Right: per-tenant edge databases with user-held keys under a blockchain anchor — local immutability via hash-anchored state transitions, no aggregate vault, blast radius capped at the breached tenant by construction (0.2% at N = 500, Sim P2, conditional on a breach). Inset: the expected-loss break-even p_device + p_commonmode < p_org, with anchors (p_org = 0.05: 15M vs 1.8M records/yr, ~8× win in the favorable region; loss at p_device = 0.06), the honest headline (variance reduction and blast-radius capping, not loss elimination), and the key/guardian-loss offset (~+1.5M record-equivalents/yr at p_key = 0.005).
**Purpose.** Make the custodianship argument visual and carry its quantified, two-sided security arithmetic in the same frame.
**Target.** Whitepaper — §3.3 (what changes for the measured) and §4.7 (harm accounting, channel 3); Figure 3 slot ("two architectures, two risk geometries").

### 9. `wp_patented_method_flow.png`
**Caption.** Patented method (US 12,236,480 B2, "Secure Decentralized System," granted Feb 25, 2025; assigned to FreshCredit, Apr 2025). Write/share lane (independent claim 1, "method for creating a secure credit report"): a first node receives new, second-node-verified commercial-actor data (410); generates a content-addressed cryptographic-hash storage identifier (420; claim 4); provides encrypted data + identifier to the distributed data sources under the tamper-resistant, permissioned structure (430); broadcasts the identifier through the network of nodes (440); and updates the commercial actor's node (450). Read/serve lane (dependent claim 2, with the claim-3 permission gate and claim-20-style token gate): device request with ID + keys (510); obtain the storage identifier from the subject's node, triggering the requester→provider token transfer (520); search the distributed data sources by content address (530); provide the data re-encrypted to the requester's public key (540); the device decrypts locally (550). The architectural split — encrypted data distributed off-chain, nodes anchoring only identifiers/permissions/incentives — is the patented basis of the custodianship shift.
**Purpose.** Establish defensible-IP backing for the implementation architecture (the W1/W3 designs), redrawn cleanly from the patent's FIG. 4/FIG. 5 flows.
**Target.** Whitepaper — §4.6 (the moat: open core, protected method); companion to the architecture and custodianship figures.

## Spec ambiguities resolved by judgment
1. **TFP vendor references.** The delegation says TFP diagrams carry no vendor names, while the TFP paper text names libSQL/Substrate/Smoldot/x402. Diagrams 1–5 therefore use generic functional names ("audit chain," "light-client verification," "micropayment settlement," "database-per-tenant") and only open *standards* (W3C DID, SD-JWT RFC 9901), which are specifications, not vendors.
2. **Five layers.** The paper's own Figure-1 caption lists five layers (measurement / identity & data / validation-compute / settlement-audit / governance-interop) while the delegation names formal objects (master law, estimator interface, attestation relation, R, ψ). Diagram 1 uses the delegation's layer functions (consumption as L5 instead of governance, since governance-by-design is cross-cutting), and places R, ψ, and the attestation boundary on a side rail as cross-cutting/population objects — matching the paper's own treatment of them.
3. **Fig. 5 phase circles.** Schematic arrows are illustrative (seeded draws); only the printed Sim P1 re-run values (0.739 ± 0.029; ≈0.04 floor) are quoted, and the figure says so explicitly — no fabricated data plot.
4. **Patent figure numbering.** The brief's FIG. 5 steps are numbered 510–570; the read lane compresses them into five steps (510–550) preserving order and content, and notes the compression in the caption.
5. **"Literal wall."** Drawn as a hatched terracotta masonry band across the full width of diagram 7 with the sequestration label on it, per the delegation's explicit instruction.
